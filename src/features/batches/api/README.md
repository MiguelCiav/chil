# batches/api

## Overview
Provides the data-access, reporting, recognition metadata, and external scraper integration layer for the `batches` feature. It encapsulates session-cached Firestore CRUD and batch-merge operations for batches and scout members (`src/lib/sessionCache.ts`), static in-memory territorial hierarchy loading from `src/data/hierarchy.json`, PDF and CSV report generation, recognition badge metadata, and scraper credential/status APIs.

## Interface
- `index.ts`: Barrel re-exporting all modules in `src/features/batches/api` (`recognitionMetadata`, `hierarchyApi`, `scraperApi`, `batchesCrud`, `membersCrud`, `batchReports`) plus `../utils/codeGenerator`.
- `batchesCrud.ts`: `generateSecureBatchId`, `commitChunkedBatches`, `buildBatchQueryForUser`, `createBatch`, `createBatchWithMembers`, `updateBatch`, `deleteBatch`, `getAllBatches`, `getBatchById`, `MergeBatchesParams`, `mergeBatches`.
- `membersCrud.ts`: `isGenericIdentity`, `getMemberDocId` (re-exported from `../utils/memberIdentity`), `MemberUpdateEntry`, `buildMembersQueryForBatch`, `buildMembersQueryForBatchChunk`, `buildMembersQueryForUser`, `sanitizeMemberForSave`, `resolveActualFirestoreDocId`, `getCachedMembersForBatch`, `resolveCachedMembersForBatch`, `seedBatchMembersCache`, `upsertMembersInCache`, `removeMembersByBatchIdFromCache`, `createMember`, `updateMember`, `saveBatchMemberUpdates`, `batchUpdateMembers`, `batchSaveMembers`, `deleteBatchMember`, `getMembersByBatchId`, `getAllMembers`.
- `hierarchyApi.ts`: `getHierarchyData`.
- `recognitionMetadata.ts`: `RecognitionTypeInfo`, `RECOGNITION_TYPES`, `BadgeStyle`, `BADGE_STYLE_RULES`, `DEFAULT_BADGE_STYLE`, `EMPTY_BADGE_STYLE`, `getRecognitionBadgeStyle`, `getRecognitionName`.
- `batchReports.ts`: `ReportBucketKind`, `ReportBucketKey`, `BatchReportBucket`, `GenerateBatchReportOptions`, `resolveBatchReportBuckets`, `filterEligibleReportBuckets`, `exportMembersToCSV`, `generateBatchReport`.
- `scraperApi.ts`: `getScraperApiUrl`, `ScraperMemberDetails`, `ScraperCredentials`, `ScraperSessionStatusState`, `ScraperSessionStatus`, `ScraperSessionErrorReason`, `ScraperSessionError`, `isScraperSessionError`, `purgeLegacyScraperStorage`, `getScraperSessionStatus`, `saveScraperSession`, `clearScraperSession`, `getMemberStatus`.

## Invariants
- `[batchesCrud.ts:generateSecureBatchId]`: Generates 9-digit numeric IDs in `[100_000_000, 999_999_999]` using `globalThis.crypto.getRandomValues` when available, falling back to `Date.now()`.
- `[batchesCrud.ts:commitChunkedBatches]`: Commits Firestore `WriteBatch` operations in chunks of `chunkSize` (defaults to `450` when omitted or `<= 0`).
- `[batchesCrud.ts:getAllBatches]`, `[membersCrud.ts:getAllMembers]`: Return `[]` when neither an explicit `userId` nor `auth.currentUser?.uid` is present; backed by two-tier caching — in-memory `createKeyedSessionCache` (`src/lib/sessionCache.ts`) + persistent 24h IndexedDB (`src/lib/persistentCache.ts`, preserving `legacyDocIds` across reloads) — with in-flight Promise deduplication and write-through updates on all mutations (`createBatch`, `createBatchWithMembers`, `updateBatch`, `deleteBatch`, `mergeBatches`, `createMember`, `updateMember`, `saveBatchMemberUpdates`, `batchUpdateMembers`, `deleteBatchMember`). `getBatchById`, `updateBatch`, `deleteBatch`, and `getMembersByBatchId` check warm caches, in-flight promises, collection IndexedDB entries (`batches:${uid}` / `members:${uid}`), and UID-scoped per-batch cold caches/IndexedDB entries (`coldBatchesByIdCache` / `batch:${uid}:${id}`, `coldMembersByBatchCache` / `batch_members:${uid}:${batchId}`) before querying Firestore.
- `[batchesCrud.ts:createBatchWithMembers]`: Pre-generates a 9-digit `batchId`, persists optional `code_mode` when provided (never writing `undefined`), and commits `batches/{batchId}` plus all stamped `scout_members` in a single `WriteBatch` (for `<= 449` members; chunked via `commitChunkedBatches` otherwise) before syncing warm session caches.
- `[batchesCrud.ts:mergeBatches]`: Deduplicates `params.batchIds` and requires at least 2 valid existing batches; fetches source members first to compute `mergedCodeMode` via `inferBatchCodeMode` (shared mode if all agree, `'manual'` if mixed); resolves duplicate non-generic identities deterministically via `deduplicateMergedMembers` (`active > exceptional > pending`, newest `created_at`, highest numeric `batch.id`, same-tier `recognition_code` fallback, generic `_2`/`_3` doc-ID disambiguation); preserves shared metadata (`region_id`, `district_id`, `group_id`, `unit_scope`, `recognition_duration`, `recognition_type`), commits in a single atomic `WriteBatch` when `<= 450` ops or create-before-delete chunks when `> 450` ops, and updates warm caches via write-through.
- `[membersCrud.ts:isGenericIdentity]`, `[membersCrud.ts:getMemberDocId]`: Re-exported from `../utils/memberIdentity`.
- `[membersCrud.ts:saveBatchMemberUpdates]`, `[membersCrud.ts:deleteBatchMember]`: Track non-canonical legacy `docSnapshot.id` outliers privately via `legacyDocIdByCanonicalKey` (`createKeyedSessionCache`); `saveBatchMemberUpdates` atomically writes `set(newDocId)` and deletes `oldActualDocId` whenever doc IDs differ, evicting stale doc IDs from warm caches before upserting; `deleteBatchMember` deletes the exact actual Firestore doc ID and evicts only that canonical doc ID from caches.
- `[membersCrud.ts:getMembersByBatchId]`, `[membersCrud.ts:getAllMembers]`: Deduplicates non-generic members per batch via `normalizeCedula` (prioritizing entries with `recognition_code`, never collapsing distinct identities that share a manual code) while preserving all generic-identity (`S/C`) records.
- `[hierarchyApi.ts:getHierarchyData]`: Serves normalized `regions`, `districts`, and `groups` directly from bundled `src/data/hierarchy.json` (ensuring `{ id: 0, name: "No aplica" }` at index 0, sorted by `id` ascending) and returns shallow copies on every call with 0 Firestore reads or writes.
- `[recognitionMetadata.ts:getRecognitionBadgeStyle]`, `[recognitionMetadata.ts:getRecognitionName]`: Pure lookups with deterministic fallbacks (`EMPTY_BADGE_STYLE`/`DEFAULT_BADGE_STYLE` and `'-'`/input string).
- `[batchReports.ts:resolveBatchReportBuckets]`: Ignores synthetic `{ id: 0, name: "No aplica" }` hierarchy entries; routes `unit === 'no_scout'` to `'special:no_scout'` (`"Miembros no scout"`), otherwise resolves `member.group_id ?? batch.group_id` via `group -> district -> region`, and routes `0` or unresolved positive IDs (with `console.warn`) to `'special:ungrouped'` (`"Sin grupo asignado"`); sorts Scout groups and members alphabetically (`es` locale, `sensitivity: 'base'`, `identity` tie-break) with non-empty special buckets pinned last.
- `[batchReports.ts:filterEligibleReportBuckets]`: Filters each bucket's `members` to eligible statuses (`status === 'active' || status === 'exceptional'`) and drops buckets whose filtered member list is empty without mutating the input array or bucket objects.
- `[batchReports.ts:generateBatchReport]`: Accepts optional 4th `options?: GenerateBatchReportOptions` (`{ bucketKey? }`); throws `"Lote no encontrado"` if the target batch does not exist, `"No hay miembros en este lote para generar el reporte."` when `members.length === 0`, and `"El grupo seleccionado no tiene miembros en este lote."` when a supplied `bucketKey` has no bucket; computes `"Total"`, `"Activos (Válidos)"`, `"Excepcionales"` (`status === 'exceptional'`), and `"Pendientes"` from the exported members slice; prevents orphaned section headers near `PAGE_BOTTOM_Y = 275`, repeats `"(Continuación)"` + table headers on mid-section page breaks, and logs a warning via `console.warn` on unresolved positive group IDs.
- `[scraperApi.ts:getScraperApiUrl]`: Strips trailing slashes from `VITE_SCRAPER_API_URL`.
- `[scraperApi.ts:purgeLegacyScraperStorage]`: Clears any legacy `chil_scraper_credentials` entry from `window.sessionStorage` and `window.localStorage` without persisting credentials in the browser.
- `[scraperApi.ts:getScraperSessionStatus]`, `[scraperApi.ts:saveScraperSession]`, `[scraperApi.ts:clearScraperSession]`, `[scraperApi.ts:getMemberStatus]`: Route via authenticated HTTP `fetch` (`Authorization: Bearer <idToken>`) when `getScraperApiUrl()` is non-empty, or Firebase `httpsCallable` otherwise, and normalize `SCRAPER_NOT_CONFIGURED`, `SCRAPER_SESSION_EXPIRED`, and `UNAUTHENTICATED` errors into `ScraperSessionError`; `saveScraperSession` throws a plain `Error` for invalid Impeesa credentials (`unauthenticated` callable code or HTTP `401` with `reason === 'IMPEESA_INVALID_CREDENTIALS'`).

## Side Effects
- `[batchesCrud.ts:createBatch]`, `[batchesCrud.ts:createBatchWithMembers]`, `[batchesCrud.ts:updateBatch]`, `[batchesCrud.ts:deleteBatch]`, `[batchesCrud.ts:getAllBatches]`, `[batchesCrud.ts:getBatchById]`, `[batchesCrud.ts:mergeBatches]`: Read, write, and batch-delete documents in Firestore `batches` and `scout_members` collections.
- `[membersCrud.ts:createMember]`, `[membersCrud.ts:updateMember]`, `[membersCrud.ts:saveBatchMemberUpdates]`, `[membersCrud.ts:batchUpdateMembers]`, `[membersCrud.ts:deleteBatchMember]`, `[membersCrud.ts:getMembersByBatchId]`, `[membersCrud.ts:getAllMembers]`: Read, write, batch-write/migrate, and delete documents in Firestore `scout_members` collection.
- `[hierarchyApi.ts:getHierarchyData]`: None (pure in-memory read from bundled `src/data/hierarchy.json`).
- `[batchReports.ts:exportMembersToCSV]`: Mutates `document.body` with a temporary `<a>` element, creates/revokes a `Blob` object URL, and triggers a browser CSV download.
- `[batchReports.ts:resolveBatchReportBuckets]`, `[batchReports.ts:generateBatchReport]`: `generateBatchReport` optionally reads Firestore via `getBatchById` and `getMembersByBatchId` (and reads bundled hierarchy data in memory via `getHierarchyData` with 0 Firestore reads) and saves a PDF file (`Reporte_Lote_${batch.id}.pdf`, or `Reporte_Lote_${batch.id}_${slug}.pdf` when scoped by `options.bucketKey`) via `jsPDF.save`; both functions log via `console.warn` on unresolved positive group IDs.
- `[scraperApi.ts:purgeLegacyScraperStorage]`: Removes any legacy `chil_scraper_credentials` key from `window.sessionStorage` and `window.localStorage`.
- `[scraperApi.ts:getScraperSessionStatus]`, `[scraperApi.ts:saveScraperSession]`, `[scraperApi.ts:clearScraperSession]`, `[scraperApi.ts:getMemberStatus]`: Call `auth.currentUser.getIdToken()` and perform authenticated HTTP `fetch` requests (`Authorization: Bearer <idToken>`) when `getScraperApiUrl()` (`VITE_SCRAPER_API_URL`) is non-empty, or Firebase `httpsCallable` invocations otherwise, and log errors to `console.error`.
