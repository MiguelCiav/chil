# Batches Feature Blueprint

## System Overview
The `batches` feature subsystem manages the full lifecycle of recognition batches: batch creation (via a multi-step wizard with Scout registry scraping, hierarchy matching, and unit inference), batch listing with multi-criteria filtering and batch merging, batch detail inspection and member management, and PDF/CSV/ZIP report generation.

## Local Interface & Invariants
- **Public Barrel (`index.ts`)**:
  - `index.ts:*` re-exports `./components/NewBatchWizard`, `./components/BatchDetail`, `./components/BatchList`, `./types`, and `./api`.
  - **Invariants**: None (pure barrel re-export module).
  - **Side Effects**: None.

## Subdirectories & System Boundaries
- **API**: [`./api/README.md`](./api/README.md) - Firestore CRUD for batches and members, Scout hierarchy seeding/fetching, recognition metadata lookups, CSV/PDF batch reporting, and Scout registry scraper integration.
- **Components**: [`./components/README.md`](./components/README.md) - Top-level workflow and page views (`BatchList`, `BatchDetail`, `NewBatchWizard`) and their nested subcomponents (`./components/detail/README.md`, `./components/list/README.md`, `./components/shared/README.md`, `./components/wizard/README.md`).
- **Hooks**: [`./hooks/README.md`](./hooks/README.md) - `useCertificateZipDownload` (shared certificate ZIP progress/cancellation), `useScraperSessionGuard` (shared Impeesa session verification and alert modal state), and `useBatchReverification` (post-emission Impeesa re-verification pool and two-phase manual code staging).
- **Types**: [`./types/README.md`](./types/README.md) - Feature-level TypeScript type re-exports (including `BatchCodeMode`).
- **Utils**: [`./utils/README.md`](./utils/README.md) - Pure helpers for member identity normalization/doc IDs (`memberIdentity.ts`), recognition code generation/mode inference/validation (`codeGenerator.ts`), shared scraper verification pool and re-verification transitions (`scraperVerificationPool.ts`), deterministic merge deduplication (`memberMerge.ts`), Scout hierarchy matching/classification, full-name splitting, age/scope-based unit inference, and read-time multi-territory batch projection and breakdown (`batchTerritorial.ts`).
- **Shared Cross-Feature Resolver (`../../utils/memberHierarchy.ts`)**: Canonical member-first hierarchy resolver (`resolveMemberHierarchy`, `isNoAplicaDistrict`) shared across `batches`, `summary`, and `statistics`.

## Read-Time Territorial Projection Flow
- `BatchList` indexes fetched `ScoutMember[]` records by `batch_id` and projects each batch via `batchTerritorial.ts:deriveBatchTerritorialProjection` -> `src/utils/memberHierarchy.ts:resolveMemberHierarchy`, rendering count-sorted multi-territory pills (`<= 3 + +N`) and exact key-based filters without mutating Firestore `batches` documents.
- `BatchDetail` computes `batchTerritorial.ts:calculateBatchTerritorialBreakdown` for `BatchTerritorialCard`, and `batchDetailColumns.tsx` / `MemberQuickViewModal.tsx` delegate group lookup directly to `src/utils/memberHierarchy.ts:resolveMemberHierarchy`.

## Global Invariants
- **Authentication & User Scoping**: `batchesCrud.ts:getAllBatches` and `membersCrud.ts:getAllMembers` return `[]` when no `userId` or `auth.currentUser?.uid` is available; `batchesCrud.ts:mergeBatches` requires at least 2 valid existing batches.
- **Member Identity & Deduplication**: `memberIdentity.ts:getMemberDocId` (re-exported by `membersCrud.ts`) prefixes document IDs with `${batch_id}_` when valid and distinguishes generic identities (`isGenericIdentity`: `S/C`, `N/A`, `NO_DISPONIBLE`, `SIN CEDULA`, `NONE`, empty); `membersCrud.ts:getMembersByBatchId` deduplicates non-generic identities via `normalizeCedula` while preserving all generic (`S/C`) members and distinct people sharing a manual `recognition_code`; `membersCrud.ts:saveBatchMemberUpdates` atomically migrates changed doc IDs (`set` + `delete`) and `deleteBatchMember` deletes exact doc IDs (including recorded legacy non-canonical IDs); `batchesCrud.ts:mergeBatches` deduplicates colliding non-generic cédulas deterministically (`active > exceptional > pending`, newest `created_at`, highest numeric `batch.id`, same-tier code fallback).
- **Recognition Eligibility, Codes & Post-Emission Immutability**: `Batch.code_mode` (`'auto' | 'manual'`) is persisted on create/merge with `inferBatchCodeMode` read-time fallback for legacy batches; post-emission (`BatchDetail` / `EditMemberModal` `lifecycle="emitted"`), `identity` is locked for Scout `active` members (editable on `pending`, `exceptional`, and `no_scout`), `recognition_code` is locked once assigned, `exceptional` checkbox is locked once saved with a code, and `unit` cannot cross the `Scout <-> no_scout` boundary; re-verifying `pending`/`exceptional` members against Impeesa issues a new locked code on activation (`auto` or two-phase `ManualCodeAssignmentModal`) without reusing prior exceptional codes. `batchDetailColumns.tsx:renderMemberActionsCell` gates single-certificate PDF downloads on eligible (`'active'` / `'exceptional'`) members and blocks deleting the last remaining member (`members.length <= 1`).
- **Non-Scout vs. Registry Verification**: `unitInference.ts:inferBatchMemberUnits` (exported utility, not invoked by `NewBatchWizard`) and `EditMemberModal.tsx` force `status: 'active'` when `unit === 'no_scout'`; in `NewBatchWizard`, Step 1 queries the Scout registry for entered cedulas (with `wizardHelpers.ts:buildUnregisteredMemberRecord` setting `status: 'pending'` and `verified_in_registry: true` on unregistered fallbacks), while `Step2ReviewConfirm` (via `ManualMemberModal.tsx`) also allows adding manual Scout members (`unit !== 'no_scout'`) directly with `status: 'active'` and `verified_in_registry: true` without querying the registry.

## Global Side Effects
- **Cloud Firestore**: Reads and writes `batches` and `scout_members` collections (backed by `src/lib/sessionCache.ts` UID-scoped in-memory caching with write-through updates and single-`WriteBatch` `createBatchWithMembers` emission); serves territorial hierarchy (`regions`, `districts`, `groups`) directly from bundled `src/data/hierarchy.json` in `api/hierarchyApi.ts` with 0 Firestore reads/writes; and delegates `recognition_types`/`recognition_templates` reads to `../recognitions` (`getAllRecognitionTypes`, `getRecognitionTypeById`).
- **External Scraper / Backend API**: Routes `getScraperSessionStatus`, `saveScraperSession`, `clearScraperSession`, and `getMemberStatus` via authenticated HTTP `fetch` (when `VITE_SCRAPER_API_URL` is configured on Vercel) or Firebase `httpsCallable`, using server-encrypted Impeesa session cookies.
- **Browser Storage & DOM**: Purges legacy `chil_scraper_credentials` keys from `sessionStorage`/`localStorage`; manages `document` `mousedown`/`keydown` listeners (`ScopedExportSplitButton.tsx`) and toast auto-dismiss `setTimeout` timers; triggers `window.alert`, `window.confirm`, `Blob` CSV file downloads (`batchReports.ts:exportMembersToCSV`), `jsPDF.save()` PDF report downloads (`batchReports.ts:generateBatchReport`), delegated certificate PDF/ZIP exports (`../recognitions`), client-side navigation (`useNavigate`), and `console.log`/`console.warn`/`console.error` logging.
- **Cryptography**: Uses `crypto.getRandomValues` in `codeGenerator.ts:generateRecognitionCode` and `batchesCrud.ts:generateSecureBatchId`.
